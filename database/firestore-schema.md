# PPLG League Firebase Firestore Schema

## Collections Structure

### Collection: `users`
Document structure for user/team registration (the person who controls the team):

```typescript
{
  id: string,           // Auto-generated by Firestore
  name: string,         // User's real name
  team_name: string,    // FC 26 team name (unique)
  created_at: Timestamp // Firestore timestamp
}
```

**Index**: Create composite index on `team_name` for uniqueness validation

### Collection: `game_players`
Document structure for actual FC 26 players in each team:

```typescript
{
  id: string,           // Auto-generated by Firestore
  user_id: string,      // Reference to users document (who owns this team)
  team_name: string,    // FC 26 team name
  player_name: string,  // Actual FC 26 player name (e.g., "Mbappe")
  created_at: Timestamp // Firestore timestamp
}
```

**Indexes**: 
- Composite index on `user_id`
- Composite index on `team_name`

### Collection: `matches`
Document structure for match fixtures and results:

```typescript
{
  id: string,              // Auto-generated by Firestore
  home_user_id: string,    // Reference to users document (home team owner)
  away_user_id: string,    // Reference to users document (away team owner)
  home_team_name: string,  // Home team name
  away_team_name: string,  // Away team name
  home_score: number | null,
  away_score: number | null,
  status: 'scheduled' | 'played',
  round: number,           // Match week/round number
  phase: 'league' | 'tournament', // League phase or tournament phase
  tournament_round?: string, // For tournament: 'quarter_final', 'semi_final', 'final'
  updated_at: Timestamp    // Firestore timestamp
}
```

**Indexes**: 
- Composite index on `status` and `round`
- Composite index on `round` and `updated_at`

### Collection: `stats`
Document structure for player statistics:

```typescript
{
  id: string,          // Auto-generated by Firestore
  match_id: string,    // Reference to matches document
  player_name: string, // Game player name (from game_players collection)
  team_name: string,   // Team name
  type: 'goal' | 'assist',
  count: number,       // Number of goals/assists
  created_at: Timestamp // Firestore timestamp
}
```

### Collection: `league_config`
Document structure for league configuration (single document):

```typescript
{
  id: string,              // Always "config"
  status: 'registration' | 'league_ongoing' | 'league_completed' | 'tournament_ongoing' | 'tournament_completed',
  top_4_qualification: boolean, // Whether top 4 qualify for tournament
  qualified_teams: string[], // Array of user_ids for top 4 teams
  tournament_started: boolean,
  updated_at: Timestamp
}
```

**Indexes**:
- Composite index on `match_id` and `type`
- Composite index on `type` and `count` (for top scorers/assists queries)
- Composite index on `player_name` and `type`

## Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Allow all operations for testing (CHANGE THIS FOR PRODUCTION)
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
```

**PERINGATAN**: Rules di atas mengizinkan semua operasi (read/write) untuk semua dokumen. Ini hanya untuk testing/development. Untuk production, gunakan rules yang lebih ketat di bawah:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users collection - public read, public write for registration
    match /users/{userId} {
      allow read: if true;
      allow create: if request.resource.data.team_name is string;
      allow update, delete: if false;
    }
    
    // Game players collection - public read, allow write (for admin operations)
    match /game_players/{playerId} {
      allow read: if true;
      allow write: if true;
    }
    
    // Matches collection - public read, allow write (for admin operations)
    match /matches/{matchId} {
      allow read: if true;
      allow write: if true;
    }
    
    // Stats collection - public read, allow write (for admin operations)
    match /stats/{statId} {
      allow read: if true;
      allow write: if true;
    }
  }
}
```

## Standings Calculation

**IMPORTANT**: Standings are NOT stored in the database. They are calculated on-the-fly by querying:
1. All users from `users` collection
2. All matches with `status == 'played'` from `matches` collection
3. Calculate standings based on match results

Calculation rules:
- Win = 3 points
- Draw = 1 point
- Loss = 0 points
- Sort order: Points > Goal Difference > Goals For > Team Name

## Setup Instructions

1. Create Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
2. Enable Firestore Database
3. Create the four collections: `users`, `game_players`, `matches`, `stats`
4. Apply the security rules above
5. Create the suggested indexes for optimal query performance
6. Copy your Firebase config values for environment variables

## Data Flow

1. **Registration**: User registers their team → creates `users` document
2. **Game Players**: Admin adds game players (e.g., Mbappe) to each team → creates `game_players` documents
3. **Schedule**: Admin locks registration → generates `matches` documents
4. **Match Results**: Admin inputs score + game player stats → updates `matches` and creates `stats` documents
5. **Standings**: Automatically calculated from `matches` with status 'played'
6. **Delete Operations**: Admin can delete users, matches, and stats (full tournament reset)
